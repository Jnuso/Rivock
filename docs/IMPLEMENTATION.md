## Deliberate implementation choices

- Python 3.12.14 is the tested runtime rather than the planning draft's proposed 3.13. Node 24.19.0 and PostgreSQL 17.11 are recorded in runtime files/Compose. Python and npm dependency lockfiles capture the tested versions.
- A short global PostgreSQL advisory transaction lock serializes writes for v1. Read rate counters use atomic upserts. This simplifies block/suspension/deletion/publication races at low traffic; it must be revisited before high write throughput. Provider network calls never hold this lock or a database transaction.
- The provider returns a validated structured `allow|reject|uncertain` decision and safe reason code. Uncertainty publishes/logs, failure stays pending. No numeric model confidence is treated as a calibrated safety score. The actual model/API/prices/retention must be verified before real enablement.
- Worker batches stop starting new provider work after 35 seconds to fit the proposed 60-second job timeout. Expired leases and reserved unknown-cost attempts remain recoverable/conservative.
- Retention erases terminal submission text after seven days and unresolved text after thirty days. Reports/audit free text is redacted after ninety days; AI-attempt, report and admin-action rows expire after 365 days. Minimal identity, idempotency/FK and erasure markers remain without a fixed expiry to preserve identity linkage, replay safety and restoration. This is a deliberate v1 choice, subject to later review.
- Clerk React 6.17.8 replaces MSAL. Hosted login uses safe same-origin return URLs; the API verifies Clerk user-session tokens without a Backend API secret. Issuer/subject fields replace tenant/object IDs, preserving legacy ownership without automatic account merging.
- Pending submission polling uses five seconds while visible. Drafts expire after 24 hours; text, topic, type and original revision recover together. Memory fallback survives navigation within the tab when storage is blocked, and closing the tab warns about loss. Sign-out/account changes/deactivation clear private drafts and caches.
- Thread, reply and profile edits pin their original revision through background refetches. Conflicts preserve the draft and offer the current published version, explicit replacement, or explicit rebasing before resubmission. New replies and notification links open a focused conversation with up to five safely projected structural ancestors; the user can return to normal ranking.
- Inter is packaged locally with system-font fallback. SPA SEO/link previews and real deployment cost/latency measurements remain later work.
