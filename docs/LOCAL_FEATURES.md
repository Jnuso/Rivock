## Prepared features

| Feature | Result |
| --- | --- |
| Share a thread or exact reply | Copy link generates only the canonical current-origin thread/reply route. Search terms and navigation state are omitted. Clipboard failure/absence provides a focused, selected read-only link. A pending permission request can be bypassed with Show link instead; a late response cannot replace that manual state. |
| Jump to the accepted answer | A question with a visible accepted answer offers a shortcut into the existing bounded reply context and keyboard focus. Show all answers returns to ranking. Feed cards identify accepted answers. |
| Keyboard formatting and help | Ctrl/Command+B, I and K format the current selection or cursor using the existing toolbar behavior. Typing, composition and alternate shortcuts retain native behavior; held keys do not repeatedly toggle. Formatting help explains lists, quotes, paragraphs, preview and supported links. |
| Filter all feed/search results | Conversation type: all/questions/discussions. Answer state: awaiting an answer/has an answer/accepted. Filters combine with topic, search and sort, apply in SQL before pagination, and persist in the URL. Reset filters preserves topic/search/sort; Clear search removes its incompatible sort while retaining filters. Invalid shared filters retain visible errors and can be reset. |
| Save directly from the feed | Active signed-in members can save/remove each feed card. Saved, feed and detail queries refresh together. Failed requests do not claim success; repeated clicks remain disabled through refresh. |
| Unread Alerts | All/Unread uses the existing server unread_only filter across pages, with distinct query caches, a shareable local route and read/unread labels. Mark read removes an item from Unread; the empty caught-up message appears only after a successful read. Mark all read keeps the server's existing bounded as_of cutoff. |
| Return to filtered results | Opening a feed card retains its originating topic/search/type/answer/sort in local browser history state. Back to results preserves it through accepted-answer context, parent links and Show all answers; published-reply navigation also carries it. Only validated local feed, topic, saved-list and public-profile paths are accepted. Direct/shared/new-tab links fall back to the public feed and do not carry another reader's search. |

Answer-state semantics: only published direct answers visible to the requesting viewer count. Deleted/removed/blocked-author answers and nested replies do not count. Every answer filter implies questions; discussion plus answer_status returns 422. accepted requires a visible published direct answer matching accepted_reply_id. Published descendants still contribute to the existing reply count, so a question can have surviving nested replies and remain awaiting an answer. No migration is required. OpenAPI and generated TypeScript were regenerated. User links now also carry ugc/nofollow with the existing noopener/noreferrer protections.
